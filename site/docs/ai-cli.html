AI integration

Wire Kata to your AI CLI

Kata never asks for its own AI API key. You point it at a local CLI you already use — Claude Code, Codex, Cursor, or any MCP-compatible tool — and Kata drives it on your behalf, with a scoped prompt built from the diagram surface. Your subscription pays. Your privacy terms apply. Kata is not in the middle.

What you'll be able to do

  • Recognize which AI CLIs Kata can drive and which transport each one uses.
  • Configure Preferences → AI CLI with the executable path, extra arguments, and timeout.
  • Run a round-trip test so you know the wiring works before you rely on it in a real refactor.
  • Diagnose the three failure modes people hit — path wrong, CLI not signed in, MCP transport blocked.

Supported CLIs

Kata talks to CLIs in two ways: as a shell-out that returns a unified diff, and over MCP (Streamable HTTP) so the CLI can call back into Kata for symbol resolution and smell context.

  • Claude Code — shell-out and MCP. Uses your Claude.ai / API subscription.
  • Codex CLI (OpenAI) — shell-out. Uses your OpenAI subscription.
  • Cursor — via its CLI / MCP interface. Uses your Cursor subscription.
  • Any MCP-compatible tool — as long as it can act as an MCP client and read a scoped prompt on stdin, Kata will drive it.
Kata itself is the MCP server. The CLI you configure is the MCP client. This is the opposite of how MCP is often introduced — the motivation is that Kata owns the diagram and the smell index, so the tools worth exposing (find smells, request refactor, apply diff) live on Kata's side.

Configure Preferences → AI CLI

Open Preferences → AI CLI and fill in three fields per CLI:

  1. Executable path — the full path to the CLI binary. On Windows this is typically C:\Users\<you>\AppData\Local\Programs\<cli>\bin\<cli>.exe or wherever your installer put it. If the CLI is on your PATH, the executable name alone works.
  2. Extra arguments — anything you want prepended, such as --model claude-opus-4-7 for Claude Code. Kata appends the scoped prompt after your arguments.
  3. Timeout — how long Kata will wait for the CLI to return a diff before giving up. Default 120s; raise it for large refactors.

The prompt Kata builds includes: the target class or member, the smell (or the Fowler intent) you asked for, just enough surrounding context to make the diff applyable, and an instruction to return a unified diff — nothing else. This scoping is why the round-trip is fast and why the diff usually applies cleanly.

Verify the round-trip

  1. Still on Preferences → AI CLI, click Test connection. Kata sends a trivial prompt to the CLI ("return an empty diff") and reports the round-trip time.
  2. If it fails, the log panel underneath shows exactly what Kata invoked and what came back — stdout, stderr, exit code. Ninety percent of first-time failures are one of the three cases in the next section.
  3. Close Preferences and try Right-click a 💩 badge → Ask AI on any smelly node. You should see a unified diff arrive in the AI diff preview dialog within a few seconds.

Data flow — what leaves your machine

When you invoke an AI diff apply, Kata writes a JSON prompt to the CLI's stdin (or the MCP transport, depending on the CLI). That prompt contains:

  • The target class or member's source, verbatim.
  • The surrounding context Kata deems necessary — usually immediate callers and callees, plus any types the target depends on.
  • The smell name or Fowler intent you invoked.
  • An instruction to return a unified diff and nothing else.

Once the CLI receives the prompt, wherever it sends it is governed by your agreement with the CLI vendor — Kata is not in the middle. If the CLI runs a local model (some Cursor setups, some MCP-compatible tools), nothing leaves the machine at all.

Troubleshooting

"Executable not found"

The path in Preferences doesn't resolve. Check that the file exists at that path from a fresh shell. If the CLI installs into a versioned directory, note that the path changes when the CLI updates.

CLI runs but returns "not signed in"

Each CLI has its own auth flow. Run the CLI once from a normal terminal with its login command (claude login, codex login, etc.) so it can cache credentials. Kata inherits the same credential store.

Round-trip works once, then times out

Usually the CLI is asking for interactive confirmation (a permission prompt, rate-limit acknowledgment) that a non-interactive stdin cannot answer. Pass the CLI's non-interactive flag through Extra arguments — for Claude Code that's --no-interactive; for Codex, --auto-approve.

"MCP transport blocked"

MCP over Streamable HTTP needs a local port. If your firewall is aggressive, allow Kata.App.exe to listen on localhost. This is only relevant if the CLI you configured uses MCP; shell-out CLIs are unaffected.
