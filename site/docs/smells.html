The 114 code smells Kata detects

Kata's smell index runs across every type Kata loaded and drops 💩 badges right on the class node — sometimes on the header (class-level smells), sometimes on a specific member (method-level smells). Below is what the 114 detectors are looking for, grouped by why they matter.

What you'll be able to do

  • Read a 💩 badge and know which category it belongs to, and roughly why the detector fired.
  • Filter the diagram to a single category using the smell toolbar (Fowler only, Perf only, Security only).
  • Override the threshold for detectors that use one (Long Function, Large Class, Data Class), per project or per type.
  • Jump from a badge into the Fowler intent that most commonly fixes it.

How badges appear on the diagram

  • Class-level smells — badge sits on the class header. Examples: God Class, Data Class, Refused Bequest, Feature Envy (class-scoped).
  • Method-level smells — badge sits next to the method row. Examples: Long Function, Message Chains, Long Parameter List.
  • Rainbow badge — a member that trips more than one detector gets a rotating rainbow 💩 so it visibly distinguishes from a single-smell one.

Hover a badge to see which detectors fired. Click it for the suggestion panel — which Fowler refactoring typically resolves that smell, and the option to hand it to your AI CLI.

Fowler classics (22)

The catalogue from the first chapter of Fowler's Refactoring. Language agnostic; run on every one of Kata's six adapters.

  • Bloaters — Long Method, Large Class, Long Parameter List, Data Clumps, Primitive Obsession.
  • Object-Orientation Abusers — Switch Statements (missing polymorphism), Temporary Field, Refused Bequest, Alternative Classes with Different Interfaces.
  • Change Preventers — Divergent Change, Shotgun Surgery, Parallel Inheritance Hierarchies.
  • Dispensables — Comments (as a smell), Duplicate Code, Lazy Class, Data Class, Dead Code, Speculative Generality.
  • Couplers — Feature Envy, Inappropriate Intimacy, Message Chains, Middle Man.

Every classic maps to at least one Fowler intent — see the Refactoring catalog.

Performance smells (39)

Detectors that flag code patterns known to cost measurable performance at scale. Split across four sub-waves; each detector has a deterministic rewriter so the fix is a mechanical edit rather than an AI ask.

  • Allocation & boxing — needless boxing on hot paths, LINQ materialization inside loops, string concatenation in a tight loop (Java StringBuilder, C# interpolation), array-vs-List over-allocation.
  • Collection use — Contains on a list where a set would win, Count() where Any() would do, ToList() right before an IEnumerable parameter.
  • Async / IO — sync-over-async (.Result / .Wait()), missing ConfigureAwait, blocking IO in a UI context, N+1 IO patterns.
  • Reflection & startup — reflection in a hot path, per-call type resolution that could be cached, static initializer chains that dominate startup.

Security smells (17)

Detectors from Kata's security wave (waves 1-6 plus phase 2). Each one flags a concrete failure mode with a matching hardening rewriter where the fix is mechanical.

  • Input handling — SQL string concatenation, unvalidated deserialization, path traversal via user-supplied filenames, command injection through shell-out.
  • Crypto & secrets — hardcoded keys, MD5 / SHA-1 for password storage, plaintext PII in logs, missing salt in password hashing.
  • Web & transport — missing CSRF token on state-changing requests, cookie without HttpOnly, TLS certificate validation disabled, permissive CORS.
  • Access & auth — controller action without an Authorize attribute, insecure direct object reference, over-broad access modifier on sensitive types.

Idiomatic / language-specific (27, "Wave R")

Detectors that fire because the code fights the grain of its language — code that compiles and runs, but that any veteran reviewer would rewrite. Runs per language because "the grain" is different in each.

  • Java / Kotlin — missing @Nullable where the method demonstrably returns null, Java-style getters in Kotlin, mutable var where val would suffice.
  • TypeScript — any escape hatches, union types silently narrowing to unknown, promise created and dropped.
  • Go — errors ignored via _, ineffectual assign, missing godoc on exported symbol, receiver method on a value type where a pointer method is called for.
  • C# / C++ — async void outside an event handler, LINQ across a stream that could be a projection, virtual call in a ctor.

Derivatives (9)

Detectors composed of two or more other detectors that share a common cause — surfaced separately so the fix targets the shared cause rather than any one symptom.

  • Composite God Class (Large Class + Feature Envy + Data Clumps on the same type).
  • Composite Message Chain (Chain length > 3 and both endpoints outside the current class).
  • Composite Reflection Hotspot (reflection + hot-path + cache-miss on the same call site).

Threshold overrides

Detectors with a numeric threshold (Long Function line count, Large Class member count, Data Class field count) can be tuned:

  1. Global — Preferences → Smell Thresholds. Applies to every project you open.
  2. Per project — a .kata/smell-thresholds.json file at the solution root overrides the global values for that project.
  3. Per type — right-click a class → Override threshold lets you exempt a specific type. Kata records the override in the same JSON file so it survives reload.

Filter toolbar

The toolbar above the canvas lets you narrow the badges to a single category — Fowler, Perf, Security, Idiomatic, or Derivative. The active toggle lights blue so you can tell which filter is on at a glance. Turning all filters off hides every badge; turning them all on shows every fired detector.
